## U11-FONT-CACHE — согласовать стабильную идентичность шрифтов

Проверить включение коммита upstream
[88c417a39455c1219b1025e057335d3f8f015f8c](https://github.com/nicoverbruggen/kobalt/commit/88c417a39455c1219b1025e057335d3f8f015f8c)
`Use stable font identities for cached Kobo layouts` в выбранную beta11 базу.
Текущий тег v1.0-beta.10 — 1796a325 — его **не содержит**: beta10 является предком
этого коммита, не наоборот. Наличие в будущем теге beta11 нужно проверить заново.

Оба решения исправляют смену font-list hash из-за случайного временного корня
распакованных системных шрифтов Kobo. Реализации не идентичны:

- Форк: SHA-256 фактических зарегистрированных systemFiles, переданный через
  SetFontFileIdentity; остальные источники сохраняют прежнюю идентичность.
- Upstream: SetContentAddressedFontDirectory исключает случайный корень;
  остаётся относительный путь с digest распакованных байтов и логическим именем.
  Полный путь по-прежнему используется для открытия файла. Особая обработка
  ограничена глобальными fonts под объявленным private prefix.

### Порядок интеграции

1. Зафиксировать точный beta11 SHA и проверить ancestry/итоговый код, включая
   последующие изменения этого механизма и FontCopies.
2. Сопоставить охват systemFiles/content-addressed directory, metadata/fallback,
   document-font scoping и lifetime font manager. Выбрать один согласованный
   механизм, не сохранять два конкурирующих исправления по инерции.
3. Если upstream полностью покрывает наш случай, удалить только ставшую избыточной
   часть 030 с отдельным обоснованием и обновлением provenance/reference/tests.
   Не удалять FB2-функции или ослаблять cache guards под видом разрешения конфликта.
4. Перенести/сохранить regression coverage: одинаковые байты при разных temporary
   roots дают стабильный font-list hash и повторно используют disk layout;
   изменение байтов меняет идентичность и инвалидирует layout; посторонние пути,
   embedded fonts и document scope сохраняют свою семантику.
5. Выполнить native/Qt5/package CI и отдельную проверку устройства после перезапуска.
   EPUB и FB2 проверить отдельно. Parsed cache hit или быстрый повтор с retained
   document не считать доказательством reuse сохранённой вёрстки.
6. Возможную одноразовую перестройку старых layouts из-за смены формата identity
   описать отдельно; не обещать совместимость кэшей без проверки.

До этого этапа текущий механизм 030 остаётся на месте. Отчёт об исходном
исправлении: [057](057-upstream-system-font-cache-report.md).
