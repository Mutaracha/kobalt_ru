# FB2 Hybrid: выигрыш, сложность и отказоустойчивость

Основание: пользователь просит оценивать остаток работ по выигрышу во времени против
сложности отладки/надёжности и откладывать малозначительные оптимизации. Это triage,
не новый benchmark и не разрешение менять EPUB алгоритмы. Бинарник — eafb6161.

## Данные и пределы вывода

Две реальные FB2: cold time-to-reading сокращён примерно с 8.6–9.6 до 5.1 s
и с 26.6–27.5 до 9.8–11.5 s. Последний Hybrid книги1 — 4.862 s. Основной
практический выигрыш уже получен. Не сравнивать эти числа с retained 2.7 s как
с доказательством оставшегося резерва: retained пропускает другую работу.
Ручной stopwatch имеет около ±0.5 s погрешности на измерение.

При disk miss книги1 полная пагинация около 4.2 s, при cold prefix около 1.0 s.
Это бюджет работы движка, не обещание ускорить весь UI ещё на столько же.
Последний disk hit model_load=6.207 s не содержит completed session reading и
не показывает, сколько времени можно устранить. Диапазон результата неизвестен.

## Решения по задачам

| Задача | Возможный выигрыш | Цена / риск | Решение |
|---|---|---|---|
| Проверка исправленного cache save/reboot reuse | Сохранить достигнутый выигрыш; избежать повторной полной пагинации, без нового алгоритма | Низкая цена проверки, низкий риск; это приёмка уже сделанного исправления | Выполнить короткий целевой прогон, не расширять механизм кэша |
| Медленный cached layout | Может быть заметным, только если регулярно повторяется лишняя вёрстка; по текущему последнему hit выигрыш не измерен | Ограниченная диагностика дёшева; вмешательство в совместимость layout/adoption рискованно | Один целевой диагностический этап. Без воспроизводимого существенного резерва — deferred, без speculative fix |
| Дополнительный tuning cold prefix | Дополнительный выигрыш не установлен; текущие 41–63% уже получены | Меняет границу prefix, повышает риск synchronous fallback/расхождения первого кадра | Deferred: нет основания усложнять работающий путь |
| Частичное открытие сохранённой середины | Не измерено; при рабочем full cache польза может быть мала | Высокая сложность source anchors, dependencies/notes, reflow/adoption и recovery | Deferred, не этап закрытия текущей очереди |
| Полноценная секционная FB2-модель | Возможна польза для больших книг без кэша, но текущий prefix уже решает первый старт | Очень высокая сложность: XML body/sections не EPUB spine, notes/images/cross-links, completion/позиции | Deferred до отдельного сценария с доказанной потребностью и нового согласования |
| Проверки корректности/lifetime | Не ускоряют чтение; уменьшают риск потери позиции/некорректного total/аварии | Средняя цена при полном corpus, малая для выбранных границ | Выполнить ограниченный regression gate; расширенную combinatorial matrix отложить |

## Ограниченный gate для закрытия FB2-части

1. Не переписывая движок, сопоставить уже существующие regressions с тремя группами:
   prefix→full/native anchor/count, cross-reference notes/images и незавершённая
   background work при close/cancel/lease revocation. Добавлять только конкретные пробелы.
2. Короткая device-проверка disk save/reboot/open обеих книг; отделять режимы и retained.
   Не требовать новой cold серии ради уже подтверждённого ускорения.
3. Медленный cache hit разбирать только при повторении: same source/layout/settings,
   model load/parse/paginate и session reading. Не ослаблять identity/layout guards.
4. Рабочий ориентир для дальнейшей оптимизации — воспроизводимая экономия порядка
   секунды и более до читаемой страницы, превышающая разброс, при локальном исправлении.
   Это правило triage, не измеренный результат и не универсальный performance SLA.
   Доли секунды на фоне нынешней погрешности не оправдывают риск архитектурного изменения.
5. Если существенный резерв не подтверждается либо исправление требует широкого
   вмешательства в общий EPUB/ReaderSession — перевести оптимизацию в deferred.
   Ошибки корректности не оправдывать малой экономией времени: исправить или сохранить
   безопасный whole-book fallback. Не закрывать freeze без доказательств.

EPUB recheck и старый freeze не являются обещанием FB2-ускорения. Без нового beta10
воспроизведения они не блокируют завершение согласованного FB2 feature scope.
Новая UI-функция строки состояния — отдельный пункт плана, без фоновой дополнительной
пагинации; она должна читать те же готовые значения/formatter, что и BookPage колонтитула.
