# 034: проверочная сборка native FB2 startup prefix

> Поэтапный отчёт: статусы относятся к указанному runtime. Текущее состояние и
> пакет — [сводный журнал](README.md), действующие проверки — [beta10](../../validation/beta10-device.md).

## Цель и отличие от полного проекта Hybrid

Проверить на устройстве экономию времени до первого читаемого кадра за счёт
неполной стартовой пагинации. XML/DOM, metadata, native FB2 IDs, notes и binary
остаются полными. Первый parse/style/markers и сбор данных интерфейса не убраны.
CPU-проверка не заменяет пользовательский tap-to-text замер на ARM.

Это ограниченный **startup-prefix эксперимент**, не готовая поддержка всех
FB2 slices. Полный native FB2 layout строится через существующий Hybrid scheduler
в спокойные моменты чтения. CREngine не запускается свободно в двух потоках.

## Условия включения

- Rendering mode Hybrid / runtime chapterMode включён.
- Raw FB2, без готового полного parsed cache.
- **Нет сохранённой позиции** и явных runtime window keys (background/full load).
- Ровно один основной body, кроме notes/comments; непустое name у главного body
  допускается (есть в «Виртуальном свете»).
- Текст длиннее двух бюджетов диапазона. По умолчанию бюджет — существующие
  25 расчётных страниц, это не фиксированное число фактических страниц.
- Переменная KOBALT_FB2_HYBRID=0 может отключить эксперимент; для device A/B
  достаточно обычной настройки Accurate, не требуется менять окружение.

Кэш сначала проверяется обычным полным путём. Cache-hit, сохранённая позиция,
маленькая книга, несколько основных body и Accurate остаются full-document.
Таким образом, повторное открытие существующей книги **не является тестом**
этого cold-start пути. Изменять пользовательскую базу/кэши автоматически нельзя.

## Граница диапазона и безопасный полный fallback

Первая проба обычного block-aligned cut в native FB2 не прошла регрессионный
тест: диапазон действительно рендерился коротким, но поиск безопасной границы
расширял его до целой книги. Такой пакет пользователю не выдаётся.

В этом эксперименте второй slice не открывается. Во временном layout оставляется
запас: для чтения используется первая половина полученных страниц. При достижении
границы, переходе к удалённой позиции/сноске или по проценту ридер принимает готовый
full layout, а если он ещё не готов — синхронно открывает полный документ. Может
быть заметная пауза; событие fb2-startup-promote объясняет причину. Длинный блок
может сам превысить начальный бюджет. Первые страницы и сохранение native якоря
проверяются относительно Accurate; аппаратные особенности ещё требуют проверки.

До полной готовности глобальные page counts не выдаются как точные. После
готовности полной модели доступны её точные страницы; принятие модели использует
тот же XPointer. EPUB spine не эмулируется, persistent позиции не мигрируют.

## Кэш

Prefix не пишет файл под fingerprint полного документа: имя модели отделено,
прямое сохранение prefix запрещено. После готовности full-модели вызовы cache save
делегируются ей; следующая сессия должна получить обычный full cache hit.
Закрытие до готовности full-модели может не создать новый кэш — отдельный случай
для логов. Нельзя оценивать repeat-open по нему как по гарантированно готовому кэшу.
Fingerprint/policy/проверка изменившегося файла и пороги кэширования сохранены.

## Диагностика

Сохранены штатные opening/session/cache/full-document события. Добавлены:

- `fb2-startup-plan`: slice, chapter_mode, cache_hit, saved_position,
  explicit_window, characters, slice_budget. Показывает, был ли активен опыт.
- `fb2-startup-layout`: pages, visible_pages, slice_end, characters, extra,
  layout_ms. layout_ms — хвост после основного Render, а не весь tap-to-text;
  основной счётчик — model_paginate_ms из штатной статистики.
- `fb2-startup-promote`: turn-boundary / position-outside-prefix / fraction-jump.
- В resource stats: `fb2_startup_slice`, model_parse_ms/model_paginate_ms/cache_hit.

Не считать loading first-frame читаемым текстом. Сопоставлять session reading
с фазами и пользовательским наблюдением; не складывать перекрывающиеся интервалы.

## Протокол устройства

1. Установить пакет полного ordered stack с 034; проверить About/source commit.
2. Для холодного сравнения использовать новые тестовые копии, без старой позиции
   и кэша. Простое переименование может оставить тот же fingerprint! В комплекте
   тестовых книг — четыре копии двух исходных FB2, различающиеся только именем
   файла и XML-комментарием после корня; оригиналы не изменяются. У каждой копии
   уникальный fingerprint. Названия внутри metadata остаются прежними.
3. Выбрать **Hybrid**, впервые открыть копии с суффиксом HYBRID. Отметить время
   появления читаемого текста; спокойно перелистнуть 3–5 раз, дать фону 30–60 с,
   проверить несколько последующих переходов. При очень быстром чтении возможен
   синхронный fallback, это не обязательно ошибка.
4. Закрыть и повторно открыть ту же копию: проверить быстрый full-cache путь.
5. Выбрать **Accurate**, впервые открыть отдельные копии с суффиксом ACCURATE,
   с теми же шрифтом/размером/полями/ориентацией. Не открывать HYBRID-копию в
   Accurate для замера cold start: к этому времени у неё уже может быть кэш.
6. Проверить сноску, переход в середину, затем close/reopen с сохранённой позицией.
   Они могут вызвать полный fallback; ускорение сохранённой середины пока не цель.
7. Приложить diagnostics ZIP и кратко порядок открытий/режим, субъективные паузы,
   скачки позиции или проблемы footer. Не удалять все пользовательские данные
   ради cold-теста. Для повторной независимой холодной серии нужны новые копии.

Суффикс имени сам режим не включает: режим выбирается в Settings.
Также в сборку включено согласованное «Закрыть Kobalt» вместо «Выйти из Kobalt».

## Проверки CI

Расширенный fb2-engine regression: большой native FB2 с именованным главным body,
неполный initial layout, равенство первого кадра Accurate, background full build,
полный page count, сохранение кэша из prefix-фасада и warm cache hit, adoption с тем
же якорем, удалённый переход, saved-position bypass и процентный fallback.
Существующие session cache/changed-source, EPUB, controls и presentation проверки
сохраняются. Итоговый runtime/run/artifact фиксируются в handoff после CI.
