# Beta10 — актуальная проверка устройства

Пакет: [eafb6161 / CI45456569246](https://github.com/Mutaracha/kobalt_ru/actions/runs/45456569246/artifacts/14952120554).
Полная ordered серия; series/native/Qt5/package/qemu PASS, не полная device-приёмка.
Сохранить весь профиль при закрытом Kobalt. Не ставить старый бинарник поверх
мигрированного профиля и не очищать пользовательские данные ради замера.

## Этап 1 — UI и логирование

Использовать **eafb6161**, не docs-only SHA. Новые fonts/menu-status ещё не реализованы
в этом бинарнике и в этот прогон не входят. Настройки текста/шрифта/полей/ориентации
сохранить одинаковыми на всём этапе cache. Не менять язык посреди замеров.

1. Открыть меню на RU, сделать снимок строки «Закрыть Kobalt»: префикс — Monotype
   Corsiva, слово Kobalt — Instrument Serif regular. Проверка EN необязательна
   для этого короткого прогона; отметить, если не выполнялась.
2. Отладка → выключить подробные логи. Закрыть книгу штатно, перезагрузить устройство,
   снова открыть Kobalt и проверить, что переключатель остался OFF. Компактные
   предупреждения/ошибки при OFF допустимы, пустой каталог логов не требуется.
3. Включить подробные логи. Оставить ON для cache-серии. После её первой перезагрузки
   убедиться, что сохранилось ON. Если переключатель неактивен или сбрасывается —
   остановить performance-серию и сообщить об этом; не изменять marker вручную.

## Этап 2 — четыре проверки дискового кэша

Использовать существующие тестовые копии двух книг с сохранённой позицией, не новые
fingerprints: «Виртуальный свет» и сборник Сорокина. Суффикс имени не включает режим:
Accurate/Hybrid выбрать в настройке. При наличии отдельных A/H копий использовать
соответствующую; не переименовывать и не редактировать XML для этого прогона.

Выполнить четыре цикла, по одному для каждой строки таблицы:

| Цикл | Режим | Книга | Время до текста, s / auto | Позиция/total после открытия | Местное время |
|---|---|---|---|---|---|
| A1 | Accurate | Виртуальный свет | | | |
| A2 | Accurate | Сборник Сорокина | | | |
| H1 | Hybrid | Виртуальный свет | | | |
| H2 | Hybrid | Сборник Сорокина | | | |

Для каждого цикла:

1. Выбрать режим, открыть нужную книгу; дождаться полного счётчика. Если за 120 s
   расчёт не завершился — зафиксировать это, сохранить логи и не считать cache готовым.
2. Записать/снять страницу и узнаваемую строку текста. Штатно закрыть книгу в систему,
   затем перезагрузить устройство. Не открывать другую книгу между подготовкой и reboot.
3. Открыть ту же книгу. Если открываете вручную — засечь от нажатия до **читаемой
   страницы**, не до обложки/экрана загрузки. Погрешность ручного измерения отметить.
   Если автозапуск уже начал её открывать, **не нажимать повторно и не прерывать**:
   записать `auto`, время и дождаться результата; tap-to-text для него не придумывать.
4. Проверить ту же позицию/текст, корректность счётчика; сделать 1–2 перелистывания
   и закрыть штатно. Медленный результат не «улучшать» повторами. Если возникла
   пауза/ошибка — записать местное время и действие, не менять сразу настройки.
5. После A1/A2 экспортировать диагностику как отдельный архив; после H1/H2 — второй.
   Не очищать предыдущие логи/профиль. Подробные логи остаются ON.

Ручной close/open без reboot — retained-путь и не заменяет эти четыре цикла.
Кэш мог уже существовать: это нормально. В логе проверяем save при подготовке,
disk hit при новом запуске, retained=false, parse/paginate/load и session reading.
Если один cache hit заметно медленнее — достаточно одного дополнительного повтора
именно этого цикла с теми же настройками, если это удобно; отдельный архив и пометка.
Без повторения не объявлять задержку постоянной и не начинать рискованную оптимизацию.

## Что прислать и как закрываем этап

- source commit из About/startup; снимок строки закрытия;
- результат OFF после reboot и ON после первой cache-перезагрузки;
- четыре строки таблицы (для auto без ручных секунд), заметки о позиции/счётчике;
- два оригинальных диагностических ZIP, отдельно проблемный повтор при наличии.

B10-UI закрывается по визуальному результату и persistent toggle. B10-CACHE — по
позиции, успешному save и disk reuse, без требования нового cold speedup.
B10-CACHED-LAYOUT: только при воспроизводимой задержке анализируем устранимый бюджет;
без заметного резерва/при высоком риске — deferred. Новых параметров кэша не вводим.

## Следующий ограниченный correctness gate — пока не весь device checklist

Сначала агент сверяет существующие регрессии prefix/full anchors/count, notes/images,
close/cancel/lease revocation. При необходимости будет отдельная короткая проверка
конкретного пробела на устройстве. Не требуются сейчас USB посреди фоновой вёрстки,
новый corpus, повтор всех шрифтов/ориентаций и новая холодная серия.
Исправление первых двух prefix total уже подтверждено пользователем на 7f47164;
оно не переоткрывается как обязательное холодное измерение.

Cold A/B требует отдельных новых fingerprint без сохранённой позиции. Warm disk
после перезагрузки не смешивать с retained close/open в одном процессе. Для cold
достаточно согласованных тестовых копий, не удалять оригинальные пользовательские данные.
Допустима пауза безопасного whole-book fallback, недопустимы пропуск/дублирование
текста, неверный якорь или ложный точный total. Не ждать бесконечно при зависании.

Результаты фиксировать раздельно: CI, cold speed, disk lifecycle, count/adoption,
UI, стресс/lifetime. Логи: [каталог данных](../../test%20%26%20diagnostic/README.md).
Исторические beta9 проверки не заменяют beta10. EPUB counter recheck и freeze
остаются отдельными пунктами плана, не разрешением менять upstream алгоритмы.
